# M1: the library bootstrap runs on Windows, 2026-11-09

Chromium 156.0.8078.88 plus jaal's layer (`engine/src/jaal`) and five hooks (`engine/patches/jaal`, 27 changed lines in 5 Chrome files), built on the Windows laptop. The plan is [docs/engine.md](../../docs/engine.md) › Milestones.

## Result

Passed on Windows. `bun engine/scripts/acceptance.ts` passed all 7 checks:

| Check | What it saw |
|---|---|
| Wrong ABI refused | A UI library reporting ABI 2 makes the engine exit with code 91. The fresh profile folder has no `Default` profile |
| Missing UI library refused | Exit code 90, no `Default` profile |
| Window and tab through the C API | The hello UI library (`crates/jaal-ui-hello`) opened one window and one tab; 8 events logged |
| No Chrome toolbar or tab strip | The native title bar and the page, nothing else: [screens/m1-window-windows.png](screens/m1-window-windows.png) |
| Helpers never load the UI library | 8 helpers (Crashpad, GPU, 2 utility, 4 renderers). `tasklist` saw each one except Crashpad's handler load `chrome.dll`, and none load `jaal_ui.dll`; the browser process does |
| beforeunload cancels a quit | The page's "Leave site?" dialog appears over the page ([screens/m1-beforeunload-windows.png](screens/m1-beforeunload-windows.png)). Cancel gives `QuitCancelled` and the browser keeps running |
| Quit ends the process | Leave gives `WillQuit`, then the process exits with code 0 |

Event order in the last run: `Started`, `TabInserted`, `TabState` (6), `QuitCancelled`, `TabState`, `TabRemoved`, `WillQuit`, `WindowClosed`.

## Build

Incremental, on top of M0's `out\Release` (same GN args, `engine/args/windows-x64-dev.gn`): 1.3 to 3.9 min per rebuild of our files plus the `chrome.dll` relink, at `-j 8`. One data point per build, not a benchmark.

## Not done in M1

- The exe and libraries keep Chrome's names (`chrome.exe`, `chrome.dll`, `chrome_elf.dll`). `chrome.dll` is a constant in Chrome's launcher and installer code, so the rename to `jaal.exe`, `jaal_engine.dll` and `jaal_elf.dll` is its own step.
- The Mac build. `chrome/BUILD.gn`'s patch also links `//jaal` into the Mac framework, but nothing has compiled it on a Mac.
- Keys: every key goes to the page, so Chrome shortcuts (Ctrl+T, Ctrl+W, Ctrl+F) do nothing yet (M2).
- Permission prompts, the find bar, the autofill bubble and the download-close prompt have no UI yet. A close with downloads running proceeds without asking.
- Popups, DevTools, app and PiP windows still get Chrome's own window (M4).

## Bugs found on the way

- A null dereference inside `views::Widget::Init`: the window observed its widget before init, and the first size report reached a dialog host that didn't exist yet. Found by linking `chrome.dll` with `/MAP` and reading the minidump's stack with `cdb`. Webium's code had the null check; the copy had lost it.
- `Widget::SetContentsView` DCHECKs on a framed window; the client view takes the contents (`SetClientContentsView`).
