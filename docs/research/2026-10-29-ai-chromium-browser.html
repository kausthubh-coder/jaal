Four decisions for you

  1. Base. Helium (GPL-3.0, updater and Web Store proxy done) or ungoogled-chromium (BSD-3, allows closed source)? I'd pick Helium.
  2. Shell UI. Chromium's C++ Views (one codebase for Mac and Windows) or AppKit like Dia (Mac only)? I'd pick Views.
  3. AI login. Users' own API keys and installed CLIs, as T3 Code does, or OpenAI's Sign in with ChatGPT program? I'd start with keys and CLIs.
  4. Platforms. Mac first, Windows later? Windows builds need another machine.

How Brave, Helium and Thorium stay current

Brave's rules rank its options. Code in its own folder comes first, then subclassing, then whole-file overrides in chromium_src, and direct .patch files come last. The goal is patches that are "trivial changes, and not nested logic changes".

Helium keeps Quilt patch files on top of ungoogled-chromium, sorted by origin (Inox, Debian, Bromite, Brave). It already runs its own self-hostable services: an extension proxy so the Web Store works without Google, updates, filter lists and crash reports. About 22k GitHub stars.

Thorium is the warning. Its maintainer writes 95% of the code alone, says it "is not always on the latest Chromium", and its newest build I found is M138, over a dozen milestones behind Chrome.

Vivaldi does this with about 60 staff. Brave's headcount wasn't found.

AI lives in a separate process

Reuse T3 Code's design (MIT): one agent server, one adapter per provider, over stdio.

Protocol details for each harness
  • Codex app-server. Newline-delimited JSON-RPC 2.0 on stdio. The flow is initialize, thread/start (model, sandbox, approval policy), then turn/start, which streams item/* events until turn/completed. Approvals arrive as server requests such as item/commandExecution/requestApproval. Browser tools go in experimental dynamicTools and come back as item/tool/call. codex app-server generate-ts emits typed bindings.
  • Claude Agent SDK. A library that runs the Claude Code binary. Define tools with tool() and createSdkMcpServer, set tools: [] to drop shell and file tools, and route approvals through canUseTool. A PreToolUse hook runs on every call, even in bypassPermissions, so put the origin check there.
  • T3 Code. apps/server/src/orchestration-v2/Adapters has CodexAdapterV2.ts and ClaudeAdapterV2.ts, on effect-codex-app-server and @anthropic-ai/claude-agent-sdk. The project calls itself "very very early", so expect churn.
  • Page reading. Accessibility-tree snapshots with element refs, as Playwright MCP does by default, cost fewer tokens than screenshots and need no vision model. Also support WebMCP, which lets sites register tools through navigator.modelContext; it's in a Chrome origin trial from M149 to M156.
  • Local AI. Chrome's built-in Gemini Nano APIs need Google-internal code. In a Chromium build they fall back to a backend that just echoes input, so bring your own runtime.
  • Tab tidy. Embed each tab's title and domain with a small local model, cluster them, then name the groups. It runs only when the user asks. This is my design; nobody has published latency numbers for it.

Off means no process runs

Copy Firefox 148, the only real AI kill switch. A CI test fails on any AI request while it's off.

Design: five rules for the off switch

Firefox's one setting blocks current and future AI features. Brave's Group Policy for Leo has inverted labels and fails on Linux, per user reports.

  • One ai.enabled setting, plus an enterprise policy that locks it.
  • The browser never spawns the sidecar while it's off, and kills it when switched off.
  • AI UI is a built-in component extension that registers only when on, and can be left out of the build.
  • No model downloads while off.
  • A CI test loads pages with AI off and fails on any request to an AI endpoint.

Logins are the legal catch

OpenAI and Anthropic both restrict apps from using a user's consumer plan. Default to API keys, or the user's own CLIs as T3 Code does.

Quotes: what OpenAI and Anthropic allow
  • OpenAI. Its docs say app-server authentication "has never been permitted for commercial or hosted services". Commercial use of a ChatGPT plan goes through Sign in with ChatGPT, a limited partner trial that's open to open-source projects.
  • Anthropic. "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits." Its Help Center says SDK use still draws on plans, so its two pages disagree.
  • Driving the user's CLIs. Fine for a personal build, a gray zone for a product.

Agents get a separate profile

Rival agents act inside the user's logged-in session. OpenAI says prompt injection is "unlikely to ever be fully solved".

Design: five controls for agent tabs
  1. Agent tabs run in their own profile, logged out by default. The user shares sites per task.
  2. The browser process, not the model, enforces which origins a task may read and write. This is Chrome's own design.
  3. Sending, buying, signing in and downloading always wait for a click.
  4. Shell and file tools stay off in browse sessions: Codex sandbox readOnly, Claude tools: [].
  5. A session holding private data can't freely navigate out. That breaks Simon Willison's "lethal trifecta" of private data, untrusted content and a way to send data out.
Evidence: published attack rates and incidents
  • Anthropic, Nov 2025: with an adaptive attacker getting 100 tries, Opus 4.5 fell for 8.0% of attacks on its own and 1.4% with safeguards. Sonnet 4.5: 13.8% and 1.9%.
  • Claude for Chrome at launch, Aug 2025: attack success fell from 23.6% to 11.2% with mitigations, across 123 cases.
  • Google, Dec 2025: a separate "critic" model that never sees page content vetoes off-task actions. Read-only and writable origin sets limit where data can flow.
  • Comet: Brave (Aug and Oct 2025), LayerX "CometJacking", Zenity (Mar 2026), and a phishing scam that took under four minutes (Mar 2026).
  • Playwright MCP's own docs say its origin allow and block lists "are not a security boundary".

Make each sidebar entry a database row, and load only the active tab at startup.

Design: five rules for a fast shell
  • A sidebar entry is a SQLite row. At startup only the active tab of the active space gets a live page.
  • Three tab states: live, frozen (keeps state, no CPU) and unloaded. Hidden spaces stay unloaded.
  • Keep the UI framework light. Moving Edge's UI from React to plain web components made it 42% faster, and 76% faster on PCs under 8 GB RAM.
  • Measure what users feel: cold start to first paint, tab and space switch time, sidebar scrolling with 5,000 rows, idle energy. Speedometer only has to match stock Chrome.
  • The AI sidecar starts on first use, stops when idle and has a memory cap. Users have filed reports of Node-based Claude Code reaching 20 GB and more.

What each rival does that's worth copying

Gone: ChatGPT Atlas (Aug 2026), Edge Copilot Mode (May 2026). Arc goes 22 Dec.

  • Aside. A password vault that lets the agent log in without seeing passwords, with per-task access and an audit log. Memory is local, editable markdown. Scheduled background tasks run in "agent tabs".
  • Dia. Tidy tabs (May 2026), automatic tab group names, Live Groups that fill from GitHub or Notion. Dia also moved page reading out of process. It dropped memory and deleted users' memory data on 24 Sep 2026.
  • Brave. The agent runs in a separate, isolated profile. Brave calls agentic browsing "inherently dangerous".
  • Chrome. A "Take over task" button, and it pauses before purchases and posts.
  • Edge Journeys. Groups browsing history into topic cards on the new tab page.
  • Firefox 148. Per-feature Available, Enabled or Blocked, and blocking also removes on-device models.

Six milestones, Mac first

Start by building Helium unchanged on the Mac mini and timing it. After that, a rebase every 4 weeks and a security build every week.

Plan: all six milestones
  1. Build Helium unchanged on the Mac mini, and time the build.
  2. Spaces, Pinned, Today and auto-archive on upstream vertical tabs. 5,000 rows restore with one live tab.
  3. Glance, compact mode, command bar.
  4. AI sidecar, browser tools, agent profile, off-switch test.
  5. MCP both ways, and local tab tidy.
  6. Signing, updates, sync, crash reports, then Windows.

What could sink it

  • Netflix. Widevine needs a Google license, refused to an open-source browser in 2019.
  • Security lag. Arc's maker named this as the reason to kill Arc.
  • No Google services. Forks lost Sync and Safe Browsing in 2021.
  • The business. OpenAI and Microsoft pulled back from AI browsers in 2026.

What I didn't verify

  • Mac mini build time: 7–9 h is my estimate.
  • How Arc's proprietary ADK embeds Chromium.
  • Web Store support in CEF's newer mode.
  • Current Widevine terms for small forks.
